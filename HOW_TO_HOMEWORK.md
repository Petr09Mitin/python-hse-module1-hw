# Как выполнять домашние задания

Эта инструкция не про Git, а про всё остальное: как подготовить компьютер, как устроено задание, что такое тесты и почему некоторые вещи в файлах трогать нельзя. Прочитайте её один раз целиком перед первым ДЗ, дальше можно возвращаться к разделу «Рабочий цикл» и чеклисту в конце.

---

## 1. Что лежит в папке с домашкой

На примере ДЗ1:

```
hw1-basics/
├── README.md            ← условие: сюжет, задания, критерии
├── task1.py … task5.py  ← здесь вы пишете решение
├── task6.py             ← задача со звёздочкой (по желанию)
├── data/                ← примеры данных для ручной проверки
├── public_tests/        ← публичные тесты, их можно запускать у себя
├── conftest.py          ← служебный файл для pytest
└── requirements.txt     ← список библиотек, которые нужны для проверки
```

Ваша зона ответственности только `task*.py`, и внутри них только тело функции. Всё остальное (`data/`, `public_tests/`, `conftest.py`, `requirements.txt`, папка `.github/` в корне) оставляйте как есть: это инфраструктура, на которую опирается проверка. Если вы что-то там измените, то процесс оценки сломается и вы не получите баллов!

## 2. Подготовка: Python и виртуальное окружение

### Нужен Python 3.12 или новее

Проверьте версию в терминале:

```bash
python --version      # Windows
python3 --version     # macOS / Linux
```

### Зачем нужно виртуальное окружение (venv)

Для проверки заданий нужна библиотека `pytest`, в следующих ДЗ вероятно появятся другие. Их можно поставить «в систему», но тогда библиотеки от всех проектов на компьютере сваливаются в одну кучу, и рано или поздно двум проектам понадобятся разные версии одного пакета.

Виртуальное окружение это отдельная папка `.venv` со своей копией Python и своим набором библиотек. Всё, что вы ставите при активированном окружении, попадает туда и никому больше не мешает. Удалили папку, и окружения как не бывало. Папка `.venv` уже внесена в `.gitignore`, поэтому в репозиторий она не попадёт.

### Создаём окружение (один раз)

Откройте терминал **в корне вашего репозитория** (там, где лежит `README.md` и папки `hw1-basics/` и т. д.) и выполните:

```bash
python -m venv .venv
```

Появится папка `.venv`. Одно окружение на весь репозиторий, отдельное на каждое ДЗ не нужно.

### Активируем окружение (каждый раз, когда открываете новый терминал)

| Система | Команда |
|---|---|
| macOS / Linux | `source .venv/bin/activate` |
| Windows, PowerShell | `.venv\Scripts\Activate.ps1` |
| Windows, cmd | `.venv\Scripts\activate.bat` |

Понять, что окружение активно, просто: в начале строки терминала появится `(.venv)`.

Если PowerShell пишет, что выполнение скриптов запрещено, один раз выполните:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

и попробуйте активировать ещё раз.

### Ставим библиотеки для ДЗ

С активированным окружением:

```bash
pip install -r hw1-basics/requirements.txt
```

`requirements.txt` это просто список пакетов, `-r` говорит pip «поставь всё из этого файла». Для каждого нового ДЗ повторите команду с его `requirements.txt`.

### Если работаете в VS Code или PyCharm

Редактору нужно сказать, каким Python пользоваться, иначе он будет подчёркивать импорты и запускать код «не тем» интерпретатором.

- **VS Code:** `Ctrl+Shift+P` (на Mac `Cmd+Shift+P`) → *Python: Select Interpreter* → выберите вариант с `.venv`. После этого встроенный терминал будет активировать окружение сам.
- **PyCharm:** *Settings → Project → Python Interpreter → Add Interpreter → Existing* → укажите `.venv`.

## 3. Как устроен файл с заданием

Откроем `task1.py`:

```python
def decode_caesar_cipher(text: str, shift: int) -> str:
    """
    Расшифровать text, зашифрованный шифром Цезаря со сдвигом shift.
    ...
    Пример: decode_caesar_cipher("Khoor!", 3) -> "Hello!"
    """
    # TODO: ваш код здесь
    ...


if __name__ == "__main__":
    # Готовый код запуска - менять не нужно.
    with open("data/task1_encoded.txt", encoding="utf-8") as f:
        encoded_text = f.read().strip()

    shift = 7
    print(decode_caesar_cipher(encoded_text, shift))
```

Разберём по частям.

**Сигнатура**: строка `def decode_caesar_cipher(text: str, shift: int) -> str:`. Она говорит: функция называется так-то, принимает строку `text` и целое `shift`, возвращает строку. Аннотации `: str`, `-> str` Python не проверяет, это подсказка для вас.

**Докстринг**: текст в тройных кавычках. Это и есть точное техническое задание. README рассказывает сюжет, а докстринг перечисляет правила: что считать «грязной» записью, что вернуть в пустом случае, как быть с регистром. Проверка идёт строго по докстрингу, поэтому читайте его внимательно, особенно фразы вроде «строго позже», «если не осталось ни одной», «регистр сохраняется».

**`...` (многоточие)**: заглушка на месте тела функции. Замените строку `# TODO` и `...` своим кодом. Пока там `...`, функция ничего не делает и возвращает `None`.

**Блок `if __name__ == "__main__":`**: готовый код для ручного запуска, о нём ниже.

## 4. Почему нельзя менять имя функции и аргументы

Автопроверка не читает ваш код глазами. Тест делает буквально следующее:

```python
from task1 import decode_caesar_cipher

def test_decode_basic_word():
    assert decode_caesar_cipher("Khoor, Zruog!", 3) == "Hello, World!"
```

То есть он **импортирует функцию по имени** из файла `task1.py` и **вызывает её с определёнными аргументами**. Это договорённость между вами и тестом, как разъём у зарядки: форма разъёма должна совпадать, иначе ничего не подключится.

Что будет, если переименовать функцию, например в `decode_caesar`:

```
ImportError: cannot import name 'decode_caesar_cipher' from 'task1'
!!!!!!!!!!!!!!!!!!!! Interrupted: 1 error during collection !!!!!!!!!!!!!!!!!!!!
```

Тест даже не запускается: ему нечего импортировать. То же самое с аргументами: если тест вызывает `decode_caesar_cipher(text, 3)`, а вы переписали функцию как `decode_caesar_cipher(text)` или поменяли аргументы местами, вызов сломается или даст неверный результат.

Нельзя менять:
- имя функции;
- количество, порядок и смысл аргументов;
- имя файла (`task1.py`).

Можно и нужно:
- писать любой код внутри функции;
- заводить свои вспомогательные функции в том же файле, если это удобно (главное, чтобы исходная функция осталась на месте с прежней сигнатурой).

## 5. `return`, а не `print`

Тест сравнивает **то, что функция вернула**, с правильным ответом. То, что функция напечатала, тест не видит.

```python
def average_ctr(records):
    ...
    print(result)    # вы увидите число в терминале
                     # а тест получит None
```

```python
def average_ctr(records):
    ...
    return result    # тест получит число
```

Если функция доходит до конца без `return`, Python возвращает `None`. Когда в выводе тестов вы видите `assert None == ...`, почти всегда причина в этом: забытый `return` или `return` не на той ветке `if`.

Отладочные `print` внутри функции оставлять можно, проверке они не мешают. Но результат обязательно через `return`.

## 6. Зачем блок `if __name__ == "__main__":`

Когда вы запускаете файл напрямую (`python task1.py`), Python выполняет код внутри этого блока. Когда тест **импортирует** файл (`from task1 import ...`), код внутри блока **не** выполняется, но всё, что написано вне функций и вне этого блока, выполняется сразу при импорте.

Отсюда правило: весь ваш код живёт внутри функции. Не пишите на верхнем уровне файла `input()`, чтение файлов, вызовы функции «чтобы посмотреть». Например, `input()` на верхнем уровне при запуске тестов даст:

```
OSError: pytest: reading from stdin while output is captured!
```

и тесты этого файла (а вместе с ними, как в разделе 4, весь прогон) упадут ещё на импорте.

Хотите поэкспериментировать с вызовами, делайте это в отдельном файле-черновике (например, `scratch.py`, его можно не коммитить) или в интерактивной консоли `python`.

## 7. Что такое тесты и как их запускать

### Тест это код, который проверяет код

Тест вызывает вашу функцию с известными входными данными и сравнивает результат с ожидаемым через `assert`:

```python
assert decode_caesar_cipher("Same text.", 0) == "Same text."
```

Если выражение после `assert` истинно, тест пройден. Если ложно, тест упал. `pytest` это программа, которая находит все функции с именами `test_...`, запускает их и показывает отчёт.

### Два вида тестов

- **Публичные** (`public_tests/`) лежат у вас в репозитории. Они проверяют самые очевидные случаи: работает ли функция вообще и не падает ли с ошибкой.
- **Скрытые** лежат в закрытом репозитории и подключаются только при автопроверке. Их больше, и они проверяют граничные случаи: пустой список, ноль, отрицательные числа, максимальные значения, неожиданный регистр и т. п. Ни сами тесты, ни ожидаемые ответы вы не увидите. То есть вам нужно заранее подумать и проанализировать код, предусмотреть граничные случаи и писать код с их учетом: как в реальной разработке.

Поэтому зелёные публичные тесты означают «функция в целом работает», но не «будет полный балл». Прежде чем сдавать, спросите себя по докстрингу: а что если список пустой? А если все записи «грязные»? А если час записан без ведущего нуля? Попробуйте такие случаи сами.

### Как запускать

Все команды выполняются **из папки задания** и **с активированным окружением**:

```bash
cd hw1-basics
```

Запустить файл и посмотреть, что выдаёт функция на примере из `data/`:

```bash
python task1.py
```

Прогнать публичные тесты одной задачи:

```bash
pytest public_tests/test_task1_public.py
```

Прогнать все публичные тесты сразу:

```bash
pytest public_tests/
```

(Тесты `task5` упадут, если вы не делали задачу со звёздочкой. Это нормально, на основной балл она не влияет.)

### Как читать вывод pytest

Пока функция не написана, вывод выглядит так:

```
public_tests/test_task1_public.py FF                                     [100%]

____________________________ test_decode_basic_word ____________________________

    def test_decode_basic_word():
>       assert decode_caesar_cipher("Khoor, Zruog!", 3) == "Hello, World!"
E       AssertionError: assert None == 'Hello, World!'
E        +  where None = decode_caesar_cipher('Khoor, Zruog!', 3)
```

Как это читать:
- `FF`: каждый символ это один тест. `.` пройден, `F` упал, `E` ошибка ещё до проверки (например, при импорте).
- Строка с `>` показывает, какой именно `assert` не выполнился.
- `assert None == 'Hello, World!'`: слева то, что вернула ваша функция, справа то, что ожидалось.
- `where None = decode_caesar_cipher('Khoor, Zruog!', 3)`: с какими аргументами функцию вызвали. Можете повторить этот вызов у себя и разобраться.

Когда всё хорошо, внизу будет зелёная строка вида `2 passed`.

### Сами тесты не редактируйте

Поправить `public_tests/`, чтобы они стали зелёными, технически возможно, но это ничего не даст: при автопроверке используются исходные публичные тесты плюс скрытые. Если кажется, что тест проверяет что-то странное, перечитайте докстринг, а если сомнение осталось, напишите в чат курса. Если будет обнаружено на проверке, что вы считерили и сами заменили какие-то тесты, то мы лишим вас **целого балла за всю задачку**

## 8. Рабочий цикл

1. Прочитайте README домашки и **докстринг** функции.
2. Выпишите для себя граничные случаи, которые упомянуты в докстринге.
3. Напишите решение внутри функции.
4. `python taskN.py`: посмотрите на результат на примере данных. Похоже на правду?
5. `pytest public_tests/test_taskN_public.py`: публичные тесты зелёные?
6. Проверьте свои граничные случаи в черновике или консоли.
7. Закоммитьте и запушьте. Для этого прочитайте инструкцию по работе с гитхабом.
8. Откройте вкладку **Actions** своего репозитория на GitHub → последний запуск → вверху страницы будет строка с оценкой (доля пройденных тестов от 0 до 1) и отдельная строка для бонуса.

Задания проверяются по частям, поэтому частичное решение лучше, чем никакое. Не получается одна задача, переходите к следующей. Пушить можно сколько угодно раз, каждый пуш запускает проверку заново, но рекомендуется этим не злоупотреблять.

## Чеклист перед пушем

- [ ] Имя функции, аргументы и имя файла не изменены.
- [ ] Функция возвращает результат через `return`, а не только печатает.
- [ ] На верхнем уровне файла нет `input()`, вызовов функции и прочего кода вне функций и вне блока `if __name__ == "__main__":`.
- [ ] Блок `if __name__ == "__main__":` не тронут.
- [ ] Файлы в `data/`, `public_tests/`, `conftest.py`, `.github/` не менялись.
- [ ] Каждый `task*.py` запускается без ошибок: `python taskN.py`.
- [ ] Публичные тесты зелёные.
- [ ] Проверены граничные случаи из докстринга (пустой ввод, ноль, отрицательные значения и т. п.).

## Частые ошибки и что они значат

| Что видите | Что случилось | Что делать |
|---|---|---|
| `pytest: command not found` или `No module named pytest` | Окружение не активировано или pytest не установлен | Активируйте `.venv`, затем `pip install -r requirements.txt` |
| `FileNotFoundError: data/task1_encoded.txt` | Запускаете не из папки задания | `cd hw1-basics`, затем снова `python task1.py` |
| `ImportError: cannot import name ...` | Изменено имя функции или файла | Верните исходное имя |
| `assert None == ...` | Функция ничего не возвращает | Добавьте `return` (проверьте все ветки `if`) |
| `SyntaxError` | Опечатка в коде, незакрытая скобка, неверный отступ | Смотрите строку, указанную в ошибке, и строку перед ней |
| `OSError: reading from stdin while output is captured` | В файле есть `input()` | Уберите `input()`, данные приходят через аргументы функции |
| Публичные тесты зелёные, а балл в Actions не 1.00 | Не учтены граничные случаи из скрытых тестов | Перечитайте докстринг, переберите крайние случаи |
